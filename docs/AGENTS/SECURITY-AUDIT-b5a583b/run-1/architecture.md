# Architecture and Security Boundaries

Pocket Harness is an Android shell for DeepSeek Harness. The Android app owns the WebView, embedded Termux snapshot, native bridges, file and notification flows, device-control integrations, Shizuku transport, and a loopback engine relay. AI-visible capabilities are registered by plugins in the engine/runtime tree; the Android shell does not register model tools directly. Main components are Kotlin/Android (`app/src/main`), engine/runtime build scripts (`scripts`, `dsh-shell-termux`), plugin packages (`plugins`), and self-contained vendor/companion trees (`vendor`, `dsh-*`).

Principals include the device owner, an external app sending an Android intent or receiving a granted file URI, web content loaded by the main engine WebView or BrowserHost, model-generated tool arguments, plugin/runtime code, same-device local processes, Shizuku shell/root, package/build metadata providers, CI pull-request contributors, and release-signing jobs. Protected resources include provider credentials, app-private configuration and files, device UI and shell authority, user-selected files, persistent notifications/control decisions, engine auth tokens, release artifacts, and build provenance.

The main Android entry surfaces are exported `MainActivity` VIEW/SEND intents, an exported ADB keyboard receiver, system-bound IME/accessibility services, a protected Shizuku provider, and URI grants from FileProvider. MainFrameBridge restricts calls to the engine origin and top frame, uses a random nonce, and exposes explicit annotated methods. EngineTransport listens on `127.0.0.1:3080`, checks a relay token, then proxies to an app-private Unix socket with peer UID validation. Plugin HTTP authorization checks Host/Origin and tokens; control polling moves `op,args` from the engine to native handlers. Android shell/device tools apply session-mode, authorization, screen-scope, and audit checks. The Android file-intake path checks provider grants/source paths and file type, bounds input size, and copies into private storage; exports and chooser grants follow separate user-directed paths.

BrowserHost is a separate WebView for external pages without the main native bridge. Its navigation policy rejects selected schemes, protected engine endpoints, and literal loopback/link-local hosts, but its source documentation says it is not a DNS/network firewall. The isolated profile installs a service-worker request policy; the shared fallback uses the global CookieManager and has a distinct configuration path. The embedded Linux runtime uses PRoot and binds configured host paths. `linux_bash` is registered in the Linux runtime package, while Android bridge tools use per-session `gateFor`; the historical audit identified this as a revalidation target. Shizuku commands require the Shizuku authority path and further operation checks.

Snapshot and asset lifecycles include source acquisition, metadata/hash validation, staging, extraction, activation, refresh/rollback, and cleanup. `SnapshotExtractor` bounds entry and byte counts and applies path/symlink checks. Engine overlays are resolved in the snapshot builder from package metadata. The source-build workflow builds two copies, compares outputs, and uses a separate signing stage; the local source chain is explicitly temporary-signed. GitHub repository variables, branch protections, installed APK identity, and current device permission state are outside the checked-out source.

Local execution limits: this host has no Android SDK, ADB device, or generated `snapshot.tar.xz`; some bundled toolchains/dependencies are absent. No target-controlled tests, builds, scripts, browser, emulator, or fixtures were executed because the audit platform cannot guarantee the skill's required empty environment, external-network denial, read-only target/toolchain mounts, scratch-only writes, and hard per-process resource limits. Source checks are read-only. We found no compatible structured prior ledger/findings; the historical R3 Markdown audit is context, and its open leads are rechecked rather than carried as validated records.

Coverage starts at `app/src/main/AndroidManifest.xml`, Kotlin bridge and transport components, plugin route/tool registration, Termux/Linux runtimes, snapshot and source-build scripts, `.github/workflows`, and config/export/logging code. Companion review is selected for mobile/local IPC, client/browser security, AI/tool agency, RPC/message lifecycle, data lifecycle, supply chain/release, resource exhaustion, and HTTP authentication because each corresponding boundary is present. Cloud IAM/container classes are excluded as no cloud workload or container deployment is defined in this repository; their workflow identity and deployment-control facts remain owner-observed where relevant.
