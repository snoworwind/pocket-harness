## 3. 源码差异与来源记录

每个候选在开始实现前补齐一条处置记录：上游 SHA/PR、源文件及函数、本仓对应调用链、差异行为、复现/反例、处理方式、风险、所需设备、实施 PR 和证据目录。处理方式只能明确写“已具备”“直接提取”“按本仓边界重做”“不吸收”或“待审计”。

按 Kotlin 壳、插件工具、客户端 UI、引擎补丁、持久化/恢复、来源构建/签名、设备脚本分别登记覆盖范围。对共同祖先可证的文件查看祖先后的差异；祖先不可证的副本按固定源码树和实际调用链比较。新增/删除文件都需归类，但文件哈希不同本身不证明行为更好或存在缺陷。

实现 PR 保留原作者的版权/许可声明和固定来源链接，说明哪些代码直接提取、哪些按本仓边界重做；新增依赖先检查已有许可台账并按本仓第三方规则登记。本项只要求保留来源和检查实际许可，不预设上游所有文件都可按同一许可复制。

## 4. B：虚拟屏弹层遮挡同步

复用本仓已有语义：sidebar-bubbles.ts 已发布 data-dsh-sidebar-bubbles=open/closing/closed；native-browser-presentation.ts 在 open 和 closing 时隐藏原生浏览器，还检查可见 menu/dialog/listbox。vdisplay 客户端目前没有相同门控，其 MutationObserver 的 attributeFilter 也未包含菜单状态。此处优先补齐 vdisplay 消费端，无需先增加上游的另一套全局布尔属性。

实施步骤：

1. 从实际页面抓取菜单节点、状态属性、vdisplayBounds 下发值和原生 presenting 状态，建立能复现遮挡的基线。
2. 在 plugins/dsh-android-vdisplay/src/client/index.ts 的可见性判定中纳入本仓现有弹层状态，菜单关闭动画期间仍隐藏原生画面。菜单全部关闭后才允许恢复；隐藏的 DOM 菜单不算遮挡。
3. 将状态属性和必要的可见性属性纳入实际节点的观察范围，沿用 rAF 合帧和既有轮询兜底。发布由状态变化触发，不等下一次一秒轮询；卸载时解绑观察者、取消回调并定向隐藏当前 viewer。
4. 对照 BrowserHost 的已有交互语义检查角色弹层、拖拽、侧栏收起、页面切换和页面不可见。只补必要判据；共享判据是否抽取须由重复量和依赖方向决定，不为本修复引入跨插件强依赖。

完成标准：

- open 与 closing 期间 viewer 不遮盖菜单；最后一个可见弹层关闭后恢复，关闭其中一个弹层不能提前恢复。
- 恢复后仍是原来的显示器、会话所有者与内容；隐藏 viewer 不销毁虚拟屏，不打断模型在虚拟屏中的任务，也不抢占用户侧栏焦点。
- 覆盖菜单快速重开、旋转、WebView 重载、组件重挂、无 MutationObserver 和原生桥暂不可用；均能恢复且无残留监听器。有事件支持时不依赖轮询，缺少观察器时按现有轮询周期证明降级恢复。
- 扩充已有 vdisplay 与菜单测试，补少量行为反例；设备侧先跑 screen-scope matrix，再逐个跑 verify-vdisplay-viewer、相关菜单/状态脚本，最后做双方向 ADB 真实任务。各脚本重新解析 WebView target，不并发复用旧 target。

预期修改集中于 vdisplay 插件源码与构建产物；dsh-client-ui-responsive 仅在本仓现有信号不能表达已复现情形时修改。回滚恢复这次可见性判据与观察项，保留既有显示器生命周期。实际文件和证据回填此处。

## 5. A：输入回执及真实处理结果

本仓还有一个必须一起修正的结果来源：AdbKeyboardService.commitText/clearText 返回 Unit，忽略底层编辑调用的结果；handle 只要实例存在且 action 可识别就可能返回 true。只在 Receiver 套结果码仍可能报“已提交”。这与广播回执属于同一条结果链，纳入同一个逻辑 PR。

实施步骤：

1. 先定义服务处理结果：未就绪、无连接、请求非法、已处理、处理失败/部分处理。参考上游把批编辑与实际 commit 分开处理；批编辑不支持不能直接推导输入一定不可执行。成功结果必须来源于按 Android API 契约判读的实际编辑调用；异常和中途失败不能落成成功。若上游五类码无法表示处理失败，先在协议评审中明确兼容扩展，不能归入已提交。
2. AdbKeyboardReceiver 保留 action 白名单、nonce、API 34+ sender UID 判定。合法无序广播继续按原有授权规则处理；只有 ordered broadcast 设置结果码。不得把“无回执”改成“新增授权拒绝”。
3. 清空语义先独立证明：覆盖空光标、全选/部分选中、组合输入和超出单次读取上限的文本；读取 null 不等于空串。按 API 契约处理选区，不能直接照搬只删除选区两侧的代码。无法证明全部清空时返回未确认，不把“删除调用成功”直接写成“已清空”。
4. manage 端提取小型广播执行/解析函数，clear 和 input 独立调用、独立判读；clear 未成功就不再发送 input。保持点名组件，禁止把多次广播输出拼在一起只读最后一个结果。
5. 临时切换输入法的逻辑用 finally 收口，所有异常/拒绝/超时路径都尝试恢复原输入法；恢复前确认当前仍是本次临时切入的 IME，避免覆盖用户在期间主动切换的选择。恢复失败应单独返回可理解的状态。
6. 收窄现有“文本不一致就清空重发”的修复：没有可靠的目标身份、明确的不一致证据和清空确认时禁止重投。输入连接部分处理、结果丢失、焦点/屏幕改变或追加输入场景不得盲目清空用户原文。测试证明仍有安全场景后才保留那一条有界修复路径。

| 观察结果 | 允许报告的结论 | 后续动作 |
|---|---|---|
| 应用明确拒绝、未就绪、无连接、处理失败 | 本次失败；有部分编辑则明确状态可能已变 | 停止后续广播，不自动重放 |
| 应用处理确认 + 目标文本回读一致 | 处理成功且已观察到目标结果 | 可报告已验证完成 |
| 应用处理确认 + 回读不可用 | 仅确认接收器处理，未验证最终文本 | 返回分层证据，不写“回读一致”或“目标文本已核实” |
| 应用处理确认 + 回读不一致 | 目标结果未满足或状态已变化 | 按第 6 步的窄条件决定是否能修复；不能直接重放 |
| 旧壳默认 0 / 缺少应用码 | 不能从命令成功推出处理成功 | 回读同一目标；一致才确认，无法回读则返回未确认 |
| 未知结果码、输出解析失败、派发后超时 | 结果未知，可能已处理 | 停止并查询状态，不自动重放 |

验收同时覆盖 clear-only、Unicode/多行/引号、clear+input 的第二步失败、用户切换焦点、恢复 IME 失败、旧壳兼容，以及不启用无障碍的 ADB 路径。结果字段若有扩展，同步现有输出 schema；不新增同义工具。日志和证据使用无敏感内容的测试文本，不落输入凭据和 nonce。

代码范围：AdbKeyboardService.kt、AdbKeyboardReceiver.kt、manage 插件输入调用及必要的辅助模块。补有意义的服务结果用例和逐次广播反例，运行对应 Kotlin/插件检查。实际模型任务必须证明调用确实进入 adbkeyboard 分支，不能由默认无障碍通道代答。上游的动态隐式接收器、缺码即放行和未就绪/无连接后延时重投不随回执自动移入，具体取舍见复核报告 R2。代码、CDP 和 ADB 三层完成后才关闭本项；回滚整条新增结果链，保留原有来源授权门。

## 6. C1：离线插件清单

实施步骤：

1. 从 PluginMounts 的当前 fingerprint、可信 Hard manifest 和组合信息建立只读数据源；记录每项的 entryId、moduleName、定义层和可证明的归属。按确切身份区分 Hard/Soft，多实例不能只按包名合并。
2. 读取活动 web profile、其 bundle 选择与实际 patch，以及之后的 HOME patch。只解析数据，不加载插件或执行其代码；旧 settings.yaml 不作为活动配置。
3. 将页面分为“配置期望”“待重启的请求”“运行时实际”三个字段。RPC 不可用时实际状态显示未知，不用配置值补成运行态；不把离线读到的配置加入现有 runtime-confirmed pending 存储。
4. 对未知格式、重复身份、Hard 清单失效和来源冲突提供原因；读取失败不能伪装空列表，重复 id 不以 distinctBy 静默折叠；打开页面不启动引擎、不改配置。C1 不出现可用的写开关。

先明确支持的 YAML/组合语法范围和纯解析器选择，使用与真实 Cordis 组合器对照的夹具验证。复杂结构不支持时显示只读/无法确定，不用正则猜测其启停语义，也不为了展示清单执行未知插件。

完成标准：引擎确实停止时仍能看见已支持条目的配置和来源；Hard/未知项不可写；缺文件、坏清单、重复实例和旧配置均不被误报为健康运行。新增离线清单不得改变 PluginManagementRepository 的在线 RPC 路径和持久化语义。代码范围为新的只读解析/模型（名称在实现时确定）及 PluginManagementPage 的离线呈现；原生页面需 ADB 验证，CDP 只用于可观测的引擎/状态交界，不以 DOM 检查冒充原生 UI 验收。

## 7. C2：离线 Soft 插件启停事务

C1 验收通过并不构成 C2 的验收。此项需先完成以下设计夹具和故障注入，才接上可点击开关。

### 7.1 写入规则与并发边界

- 首选在已证明可逆的 HOME 覆盖层写本功能拥有的最小 disabled 覆盖；用户原有条目、profile 与 factory bytes 保留。enable 不能靠删除用户原有的禁用行实现，disable 不能删除插件源码或原 insert。
- 对 entryId/moduleName/定义层做确切定位，证明覆盖只影响一个 Soft 实例且不会影响 Hard。重复 key、锚点/别名或其他不支持的 YAML 结构、同名多实例无法定位时拒写。
- 写入期间必须持有与启动、刷新、Safe Mode、UndoGate、SnapshotUserData.importConfiguration 及今后语言同步等配置写者共同遵守的排他协议，且再次证明引擎已停止。仅在页面禁用按钮或写前比较哈希不构成并发保护；若无法让相关本仓写者共享该边界，先拆出前置修复，C2 不接写入口。
- 防御安全路径、软链接和父目录替换；分别记录 HOME patch 不存在与空文件，不能把二者当作同一前像。同 uid 任意代码不遵守本协议的风险仍由现有沙箱缺口约束，文件锁和摘要不宣称解决该隔离问题。

### 7.2 持久化事务与中断恢复

拟增加独立、版本化的离线操作记录，字段至少含 operationId、fingerprint、Hard 摘要、目标身份、目标相对路径、原文件是否存在、前后内容摘要、备份定位和阶段。具体文件名、容量、保留期及启动接入点在实现 PR 定稿后登记 PERSISTENT-DATA.md；它是中断恢复记录，不是 Hard 归属或授权的新来源。

| 阶段 | 写入条件和持久化内容 | 进程中断后的处理 |
|---|---|---|
| 已准备 | 受限路径校验、前像备份验证、后像解析及非目标字节差异审查完成；原 live 文件尚未变化 | live 仍等于前像则可撤销本次准备；不相等则标冲突，保留证据 |
| 替换中 / 结果待核对 | 同目录临时文件落盘后原子替换；验证 live 摘要与组合语义，按平台支持的持久化原语完成文件/目录同步 | live 等于已知后像则补做语义核对；等于前像则按未应用处理；两者皆非则不覆盖 live |
| 配置已保存、待运行核对 | 记录独立的离线期望状态；没有运行时确认 | 引擎启动前先收敛历史快照事务，再核对本记录与当前 fingerprint；不匹配或无法恢复则保持只读并明确原因 |
| 运行时已核对 | 认证 inventory 中目标状态符合期望；另查未涉条目的状态没有异常变化 | 清理已收敛的操作状态；健康 promotion 仍由原 composition digest/UndoGate 判据决定 |

写后失败的回滚只允许在 live 仍等于本事务已知后像时恢复精确前像；若已被其他写者修改，保留前后证据并报冲突，禁止盲目覆盖后来的用户编辑。原文件不存在时，也只有能证明仍是本事务创建的后像才可删除。失败注入必须覆盖替换前后、状态落盘前后和恢复阶段，不能只测函数正常返回。

### 7.3 待生效状态与恢复规则

现有 plugin_management_pending 表示“运行时已确认持久化、待重启”，离线操作不能直接写进去。新增的离线期望记录由本事务维护，只有启动后经过认证 runtime inventory 核对才转为已生效；不能只因启用布尔值相同就清掉另一代/另一实例的请求。状态冲突时展示原因，交给用户刷新或选择现有恢复入口。

Safe Mode 活跃、UndoGate 恢复中、快照事务未收敛时拒绝离线启停。启动失败继续按本仓 exact fingerprint 的 known-good 规则恢复；不得从本功能自动调用 latest、restore-last-good 或重写 HOME。用户撤销本功能的变更时，只能移除本功能拥有的覆盖，不撤销用户此前的禁用决定。

### 7.4 完成标准

- 允许路径上的成功启停，在实际 rc.2 重启后得到目标状态；其他插件、bundle 选择、配置与用户文件保留。操作成功文案只表示当前已证明的阶段。
- 所有拒绝路径证明 live 字节未变；所有回滚路径证明仅恢复本事务拥有且身份匹配的内容。跨 fingerprint、坏记录、前后像都不匹配、恢复源损坏均不得自动写文件。
- 代码层完成解析语义和中断点反例，CDP 层核对运行时 inventory/状态，ADB 层完成原生页操作、重启和恢复路径的真实任务。记录每步截图，禁止只用 RPC 直接修改代替原生页面体验。
- PR 包含实际修改的 Kotlin 职责、启动/事务执行顺序、持久化账本和必要的桥协议更新；若前置并发改动形成独立问题，单独 PR 验收后再接 C2。

## 8. 新增与细化的独立工作包

本节的源码依据集中在 [第二轮复核报告](UPSTREAM-SOURCE-REVIEW-2026-10-20.md)。F/G 拆自上游功能组合中的独立行为；H/I 先形成可审查设计和输入证据，不能因本计划列出就记为已承诺发布。

### 8.1 F：悬浮服务生命周期

- 目标：引擎未启动、已停止或引擎服务不在场时，任务划除也能由 OverlayService 自己撤掉窗口；系统空 Intent 重投递不长期恢复悬浮层。
- 最小实现：在服务自身明确启动返回策略、空 Intent 和 onTaskRemoved 的自停收口，复用本地 onDestroy 统一清理窗口/回调；不依赖上游不存在于本仓的 OverlayRecall，不顺带移入隐藏入口和面板尺寸变化。
- 保留语义：不让本修复擅自改写长期启用偏好；重新显式启用和现有权限补启仍可工作。用户停机标记、EngineService 通知与看门狗范围保持各自的职责。
- 反例：显式启动、空 Intent、任务移除、权限撤销、Activity 已销毁；引擎从未启动/已停止/运行中三种前置分别验证。正常后台切换不能等同用户关闭，避免为了消除复活而误关有效悬浮层。
- 验收：先锁定返回策略与清理职责的 Kotlin 行为用例，再用 ADB 最近任务真实划除和截图/dumpsys 证明服务/窗口事实。force-stop 不替代 task removal；单次 return 值测试也不替代真实系统回收。记录观察时段，不声称短时无窗口就证明永不重建。
- 边界：上游也承认 onCreate 可能先建窗才收到空 Intent；若本仓设备出现瞬闪，调整合法显式启动的建窗时序并补同一生命周期反例，不能把“最终自停”写成“从未建窗”。
- 交付与回滚：单独 L3 原生 PR，源码集中 OverlayService，必要时衔接 Controller；代码地图、模块职责和真实坑位同步。回滚仅撤本次策略与时序，不删除用户偏好。ARM64 来源候选及三层证据齐备后才关闭。

### 8.2 G：跨入口会话身份复用

1. 先在本仓复现：同一 child 从左栏拖入和子代理入口打开，是否出现非预期新 tab/新内容实例。记录 owner、tabId、contentId 和子会话，不根据可见标题相同判断重复。
2. 对真实 rc.2 mounted/tabsIn/openResource 契约取证，确定身份键和 owner 范围；地址的 parent/mode 变化能否视为同一 live child 必须按实际会话服务确认。上游自造 fixture 不足以证明本地可调用。
3. 复现成立后优先提取纯身份解析与局部“聚焦既有 tab”接线；避免在全局把用户主动创建的多个镜像视图合并。未知协议、外部子会话、相似但不同 ID 均透传原路径。
4. 生命周期覆盖销毁顺序、组件重挂、owner 切换、tab 已关闭及后装包装器；卸载只撤本次仍拥有的包装器，不覆盖别的装饰器，不主动删除已有镜像或改写 tab store。
5. 此项不引入 MobileWorkspaces、keepMounted 或分屏 CSS。单独 L3 客户端 PR，同步源码/package/lib，并在设备上证明同 child 跨入口不意外新增、不同 child 和主动镜像仍可用。回滚恢复原打开路径，保留已存在的内容。

### 8.3 H：双语界面与语言选择

建议按两个完整逻辑改动推进，而不是把上游涉及的所有 Kotlin/UI 文件一次覆盖：

| 子项 | 设计与范围 | 完成与失败判据 |
|---|---|---|
| H1 资源与显示适配 / L3 | 梳理本仓原生文案、通知、错误入口与注入 UI；复用已存在的 locales，系统语言从未被 Activity override 污染的 context 读取；明确未支持语言的统一回退 | 当前会话、侧栏和权限状态不因切换文案丢失；中文/英文/跟随系统及重建后的呈现一致，缺 key 有回退 |
| H2 语言选择与持久化 / L2+L3 | 固定三态偏好真源和 rc.2 locale 的 bootstrap/config 优先级；若只读 bootstrap 已能完整生效，避免新增 profile 写者；确需写配置时优先 settings revision，离线才按受限事务处理 | 偏好保存、引擎应用和 UI 重建分别有回执；同步失败不无条件返回“已保存”，回前台/重载后回读真源，旧未设置状态可升级 |

桥接必须走本仓 MainFrameBridge、注解注册、方法/通道检查与输出声明；不恢复上游直接 AndroidBridge 暴露。持久化不得照搬 rename 失败即直接覆盖，也不能在每次渲染时改 profile。协调 C2、导入、Safe Mode、UndoGate 与语言写者的排他关系，状态未确认时明确部分生效而不是再建一份自称成功的偏好。

设备矩阵包含原生管理页、Web 设置、通知/错误页、进程重建、系统语言变化和跟随系统退出强制语言；验证重载是否足够重建原生资源，不能先假定 reloadWebUI 等于 Activity recreate。H1 可按当前 locale 显示能力独立验收，H2 写入/桥面按 L2 证据关闭。

### 8.4 I：抽屉宽内容保活

- 先采集本仓冷启动收起态、首次打开与重复开合的帧耗时、内存和后台副作用，使用相同提交/设备/快照输入，多次测量保留分布。上游自报数字只作定位线索。

- 测试手机/桌面、展开/收起、settled 状态和冷启动组合；特别检查保活后没有冻结成窄轨道宽度，窄/宽断点及旋转不吞手势或把桌面改成手机抽屉。

每项按匹配源码独立验收；本轮明确选择的目标项进入候选后，从最终 main 提交重新走 ARM64 来源链，验证正式签名、覆盖升级、快照刷新完成标志、三层真实任务与两方向 UI。组合回归覆盖“虚拟屏工作时打开插件管理”“输入法临时切换失败后重试其他工作”“离线启停后启动与 UndoGate/Safe Mode”“语言同步与导入/离线写入互斥”“任务划除时悬浮层和通知独立收尾”的交界，不能只重复每项的正常路径。运行时热推证据仅限开发期对应设备树，最终 APK 重验另记。

下一步先完成前置事项表与差异处置记录，然后实施 B 的最小消费端修复；A/F/C 的原生工作在合法候选来源构建路径明确后推进；G 先复现身份问题，H/I 按明确的真源与性能输入进入。等待设备/构建决定期间，仍可完成 D 的只读差异审计、A 的选区/API 契约与协议样本、F 的启动策略、G 的真实 store 契约、C1 的组合器夹具和 C2 的状态/故障注入设计，不接设备写入口。若某项未满足验收，不纳入实际发布说明，也不把剩余需求自动改成延期：保留原范围和具体阻塞，给出可审查的替代流程后再决定交付边界。
