# 0.14.0 发布说明（versionCode 39）

覆盖安装 **v0.14.0-preview (vc38)**。若从更早版本升级，用户数据（会话、工作区、配置、凭据）不会被动到。

> **vc 已轮换**：上一版预览用掉 vc38，本版为 **vc39**。

## 版本定位

**虚拟屏与 AI 浏览器达到可用线。**

上一版（0.14.0-preview）把这两项作为**实验特性**交付：虚拟屏只完成能力探针（六环节 1/6 绿，
按 No-Go 口径**刻意不接入默认路径**，状态端点返回 404），AI 浏览器只有引擎侧面板
（壳侧宿主未落地，视口/身份下拉 disabled）。本版把两项**做完并接入默认路径**，
同时交付附件入口分流、Shizuku 通道时序修复与快照升级健壮性。

## 一、虚拟屏：让第三方 App 跑在独立屏幕上

**不进你的前台，不打断你正在做的事。** AI 可以在虚拟屏上开 App、点按钮、看界面，
你的手机照常用。

### 怎么用

对 AI 说「**在虚拟屏上打开设置**」「**在虚拟屏上开 B 站**」即可。AI 侧的调用形态是
给任意带 `screenId` 的工具传 `"virtual-N"`：

| 想做什么 | 工具调用 |
|---|---|
| 建虚拟屏 | `android_vdisplay_create` |
| 在虚拟屏上开 App | `android_app_launch { pkg, screenId: "virtual-1" }` |
| 看虚拟屏画面 | `android_screenshot { screenId: "virtual-1" }` |
| 读虚拟屏界面结构 | `android_ui_dump { screenId: "virtual-1" }` |
| 点虚拟屏上的控件 | `android_ui_click { ref, screenId: "virtual-1" }` |
| 按坐标点 | `android_ui_click { x, y, screenId: "virtual-1" }` |
| 销毁 | `android_vdisplay_destroy` |

也可以**自己操作**：右侧栏「虚拟屏」Tab 有编号切换、状态与**手动关机**按钮；
App 退到后台时会出现只读浮窗（拖角缩放、贴边内滑收起、点叉只收起不销毁）。

### 本版打通的关键路径

「把第三方 App 拉进虚拟屏」实测了四条候选路径，**只有一条成立**：

| 路径 | 实测结果 |
|---|---|
| `monkey --display` | 无此选项（monkey 没有屏幕维度） |
| shell `am start --display` | 时成时败，不可靠 |
| 应用内 `setLaunchDisplayId` | 被系统 `SafeActivityOptions` 拒绝 |
| **Shizuku 特权通道 `am start --display <id> -n <component>`** | **成立** |

### 使用前提

需要**安装、启动并授权 Shizuku**（虚拟屏依赖其特权通道）。设置页「手机控制」有 Shizuku 状态与引导。

### 本版修掉的问题

- **「选了虚拟屏，App 还是开在真机上」**：`screenId` 这个参数此前对 AI **没有说明文字**，
  实测 AI 会**直接忽略它**——于是它以为开在虚拟屏上，实际开在真机屏，并在错误前提下继续排查。
  现在参数有明确说明，工具描述也给了跨屏指引；**且当本机已有虚拟屏而 AI 忘了指定时，会主动提示**
  「要它出现在虚拟屏请带 `screenId` 重调」。
- **「截图截到的是真机屏」**：截图有一条备用通道**完全没看 `screenId`**，不指定屏幕时只截默认屏。
  AI 拿到真机画面却以为在看虚拟屏——**返回成功、图也真实，只是拍错了屏**，比直接报错更难发现。
  现在两条通道都认屏幕，并按该屏自身像素换算坐标。
- **「自适应缩放不对 / 有黑边」**：画面改为按内容宽高比等比适配并居中，不拉伸。
- **点名要的意图对不上**：AI 用编号引用界面节点时可能引用到错误位置
  （重定位时换了窗口、节点列表被复用、缓存过期太短导致反复 dump）。
  现在建树时固定窗口与节点句柄，缓存放宽到 10 分钟。
- **「点击成功却报没生效」**：拿两个不同来源的版本号做变化检测，必然判「未变」。
  现在不再做不可靠比对，并把「校验不可靠」与「点击落空」分开措辞。
- **「收起侧栏后虚拟屏画面还盖着聊天」**、**编号一直涨（虚拟屏 3 却切不回去）**、
  **创建者走了没人能关**（现在任何会话都能销毁）、**闲置占资源**（10 分钟自动回收）。

## 二、AI 浏览器：侧栏里的多页签工作台

**AI 可以同时开多个网页并自己读页面；你打开侧栏就能同时查看。**
页面是**完全隔离**的第二个 WebView——网页拿不到应用桥，也影响不到主界面。

### 怎么用

对 AI 说「**打开某网站看看**」「**查一下这个页面**」即可。AI 侧：

| 想做什么 | 工具调用 |
|---|---|
| 打开网页 | `browser_open { url }` |
| 读页面可点目标 | `browser_snapshot` |
| 点击 / 输入 / 滚动 | `browser_click` / `browser_type` / `browser_scroll` |

自己操作：右侧栏工作台有地址栏、单按钮（打开/刷新）、分辨率与 PC/手机身份切换；
多页签可同时查看。

### 本版修掉的问题

- **「侧栏一收起，AI 就读不到页面了」**：收起侧栏时页面视图被设为**完全不占位**，
  WebView 的宽高塌成 0——AI 读页面时**几乎所有可交互元素都被判为「宽高不足 1」而丢掉**
  （实测某网站 191 个元素几乎全灭）。现在收起只隐藏、保留布局，并给一个合理的非退化尺寸
  （实测 **0×0 → 450×800**）。
- **「AI 说页面有 N 个元素，但我不知道该点哪」**：快照此前**只报数量**不给目标。
  现在逐行列出可点项；元素过少时会提示切换身份档（同一网址实测 **1-2 → 135 个**节点）。
- **分辨率设置对不上**：分辨率改为**真实的 CSS 视口**，`window.innerWidth` 精确等于所选值。
- **PC / 手机身份切换**：UA-CH 走能力探测，浏览器不支持时**如实标注**，不假装完整。
- **打开配置好的身份/分辨率时报「尚未创建」**、**错误页被自己覆盖**、**滚动到底部看不全**。

## 三、附件入口：图片和文件分开

**点回形针 → 出菜单 → 选「上传附件」或「上传图片」。两项走不同的系统界面。**

- **上传附件** → 系统文件选择器（任意文件类型）
- **上传图片** → **系统相册**（照片选择器，可多选）

### 本版修掉的问题

- **「要点两下才出选择器」**：工具栏的悬浮提示会在按钮和隐藏的输入框之间插入一个元素，
  而查找逻辑假定「输入框紧跟按钮」——被插入元素挡住后就找不到，于是**不拦截点击**，
  直接走原生选择器（用户感知就是要按两下）。改为按结构查找，不再依赖相邻关系。
- **「两个入口打开的是同一个界面」**（issue #215）：壳侧此前为修一个选择器视图问题，
  把**相册分支整个删掉**了——适配层把「这是图片」正确传下去也**没人看**，两个按钮走进同一个文件选择器。
  现在按类型分流：图片走相册，其余走文件选择器。

## 四、Shizuku 通道：「第一次失败、第二次成功」

**这个现象不是网络抖动，是代码里一个确定的时序问题**：等待时间设为 4 秒，而建立连接实测约需 5 秒；
且同步对象用完后没有清理，第二次调用会**立刻返回成功**。所以「重试一次就好」是必然结果。

真正的问题是**失败提示写错了**：明明是「正在连接（等几秒就行）」，却告诉 AI「通道有问题，去设置页排查」
——实测 AI 因此**放弃特权通道、改用另一条通道，结果撞上那条通道的缺陷，整条链路崩掉**。

现在：等待预算内循环重试、连接状态正确清理，并把**「正在连接（请直接重试）」**与
**「未就绪（需去设置页）」**分成两种明确提示。

同时修掉一处**报错刷屏**：某条命令失败时同一条错误重复 40 多次、文字互相交错，回执 25 KB 全是乱码。
现在同类输出会折叠并标注次数。

## 五、快照升级健壮性

**修复一个「一个损坏目录会让之后每次启动都失败」的问题。**

异常断电/模拟器崩溃可能把解压中断，留下一个**连 root 都删不掉**的残留目录（文件系统元数据损坏）。
旧逻辑遇到它就直接抛错：刷新失败 → 回滚走同一个删除方法 → **回滚也失败** → 残留永远存在 →
**之后每次启动都失败**，用户只能清除应用数据。

现在：删除改为逐项容错（能删的删掉、删不掉的记下并继续），若仍有残留则**把整个暂存目录改名挪开**
（改名只需改动父目录项，不碰坏子项，成功率更高），再用干净目录继续升级。

> 覆盖安装后请**等待首次解压完成**（界面会显示进度），期间勿强杀应用。

## 六、修复的 issue

| issue | 内容 |
|---|---|
| **#215** | 上传图片入口变复杂 → 回形针菜单 + 图片走相册 |
| **#214 / #228 / #230** | v0.13.8 升级后启动失败 / 白屏 `Failed to load plugins` → 旧配置残留自动清理 |
| **#220** | 荣耀畅玩40 Plus 白屏 → 疑同上（需报告者提供版本与配置确认） |

**#214 的机制**：旧版本会在配置里留下一条「禁用布局服务」的记录，升级时该记录**不会被自动纠正**
→ 布局服务不激活 → **13 个界面插件全部待启动** → 白屏。全新安装走整树替换，因此复现不了。
现在每个版本会自动清理一次这类退役记录，并把原文件备份为 `.pre-<版本>.bak`。

## 已知限制

- **插件市场**：绝大多数第三方插件在手机端不一定可用（移动端与桌面端在 WebView 内核 / 文件系统 /
  权限模型 / 运行环境差异大）。以可用性验证与反馈为主，暂不建议作为生产依赖。
- **虚拟屏**：上限 1 块；跨屏拉起依赖 Shizuku 授权。
- **鸿蒙 ArkWeb（#221）**：侧栏文件预览显示「文件资源服务不可用」，根因在**上游**对 URL 的解析行为
  （鸿蒙 WebView 对自定义 scheme 不填 authority）。待上游或兼容层修复。
- **未验证项**：真机（arm64）的虚拟屏与浏览器验收待补；本版模拟器验收结论不替代真机结论。
